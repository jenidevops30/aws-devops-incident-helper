# AWS DevOps Incident Helper - Architecture Diagram

```
User Browser (React + Vite / AWS Amplify)
          |
          | HTTPS POST /analyze
          v
Amazon API Gateway (HTTP API)
          |
          v
AWS Lambda (Python 3.11)
          |
          +--> analyze incident
          +--> analyze CloudWatch logs
          +--> generate CLI diagnostics
          +--> generate runbook
          +--> generate incident report
          |
          v
Amazon Bedrock - Nova Lite via APAC Inference Profile
          |
          v
Structured JSON response
          |
          v
Browser UI
  |       |        |        |
  v       v        v        v
Analysis Logs    Runbook  Incident Report
  |                          |
  +------> LocalStorage <----+
                       |
                       +--> Markdown export
                       +--> TXT export
                       +--> Browser print / PDF
```

## Incident Reporting Flow

```
Incident Analyzer ─┐
CloudWatch Logs ───┤
CLI Generator ─────┼──> Incident Report Generator ──> Review / Export
Runbook Generator ─┤
Incident History ──┘
```

## Privacy Boundary

- Incident history is stored only in browser localStorage.
- Report generation does not add a database or server-side report store.
- The application does not connect directly to the user's AWS account.
- Generated AWS CLI commands are displayed for review only and are never executed.
- The report UI renders supplied/generated content as text rather than trusted HTML.

## Bedrock Report Contract

The `generate_incident_report` action returns:

- `incident_overview`
- `executive_summary`
- `impact`
- `symptoms`
- `evidence`
- `root_cause.confirmed`
- `root_cause.probable`
- `root_cause.unknown`
- `troubleshooting`
- `diagnostic_commands`
- `remediation.immediate`
- `remediation.long_term`
- `verification`
- `rollback`
- `prevention`
- `post_incident_checklist`

All diagnostic commands pass through the existing read-only command sanitizer before being returned to the browser.
