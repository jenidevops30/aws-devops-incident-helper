# AWS DevOps Incident Helper - Architecture Diagram

```
User Browser (React + Vite / AWS Amplify)
          |
          | HTTPS POST /analyze
          v
Amazon API Gateway (HTTP API)
          |
          v
AWS Lambda (Python 3.11)
          |
          +--> analyze incident
          +--> analyze CloudWatch logs
          +--> generate CLI diagnostics
          +--> generate runbook
          +--> generate incident report
          +--> correlate incident evidence
          |
          v
Amazon Bedrock - Nova Lite via APAC Inference Profile
          |
          v
Structured JSON response
          |
          v
Browser UI
  |       |        |        |        |
  v       v        v        v        v
Analysis Logs    Runbook  Report  Correlation
  |                          |         |
  +----------> LocalStorage <----------+
                       |
                       +--> Markdown export
                       +--> TXT export
                       +--> Browser print / PDF
```

## Incident Correlation Flow

```
Incident Description
       +
CloudWatch / Application Logs
       +
AWS Diagnostic Evidence
       +
CLI Output
       +
Previous Incident Context
       +
Runbook / Troubleshooting Context
       |
       v
Evidence-Aware Correlation
       |
       +--> Confirmed findings
       +--> Probable findings
       +--> Possible findings
       +--> Unknowns
       +--> Recommended checks
       +--> Safe diagnostic commands
       +--> Next actions
       |
       v

       |
       v
Review / Export
```

```
Runbook Generator ─┤
Incident History ──┤
Incident Correlation ┘
```

## Privacy Boundary

- Incident history is stored only in browser localStorage.
- Report and correlation generation do not add a database or server-side incident store.
- The application does not connect directly to the user's AWS account.
- Generated AWS CLI commands are displayed for review only and are never executed.
- The correlation engine analyzes only operator-supplied evidence and must not claim unsupported root-cause certainty.
- The report and correlation UIs render content as text rather than trusted HTML.

## Bedrock Correlation Contract

The `generate_incident_correlation` action returns:

- `summary`
- `severity`
- `evidence_relationships`
- `confirmed_findings`
- `probable_findings`
- `possible_findings`
- `unknowns`
- `recommended_checks`
- `troubleshooting_steps`
- `safe_cli_commands`
- `next_actions`

All correlation diagnostic commands pass through the read-only command sanitizer before being returned to the browser.

## Bedrock Report Contract

The `generate_incident_report` action returns:

- `incident_overview`
- `executive_summary`
- `impact`
- `symptoms`
- `evidence`
- `root_cause.confirmed`
- `root_cause.probable`
- `root_cause.unknown`
- `troubleshooting`
- `diagnostic_commands`
- `remediation.immediate`
- `remediation.long_term`
- `verification`
- `rollback`
- `prevention`
- `post_incident_checklist`

All diagnostic commands pass through the existing read-only command sanitizer before being returned to the browser.
